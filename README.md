# QQQ Alpha

محرك بحثي يعطي **توصيات** لعقود خيارات QQQ قصيرة الأجل (0DTE / 1DTE)، القرار فيه
للذكاء الاصطناعي لا لجدول قواعد جامد.

> ⚠️ **تنبيه**: هذا نظام تعليمي/بحثي يُصدر توصيات فقط. لا يتصل بأي وسيط ولا ينفّذ
> أوامر ولا يدير محفظة. تداول الخيارات قصيرة الأجل قد يؤدي إلى خسارة رأس المال
> بالكامل. لا شيء هنا وعد بعائد.

---

## الفكرة في سطرين

الطبقات الحسابية تحوّل السوق إلى **أرقام** (مؤشرات، مستويات، تدفق مؤسسي)، ثم يقرأ
الـ AI هذه الأرقام كما يقرأ متداول محترف الشارت — لكن بلا نسيان وبلا تحيّز وبسرعة
مللي ثانية. القواعد المكتوبة في `playbook.yaml` **إرشاد لا قانون**: الـ AI مخوّل
بمخالفتها متى برّر ذلك، وكل مخالفة تُسجّل وتُراجَع أسبوعيًا.

## التشغيل السريع

```bash
uv venv --python 3.12 .venv
uv pip install -e ".[dev]"

cp .env.example .env      # املأ المفاتيح

.venv/bin/pytest -q                       # الاختبارات
.venv/bin/qqq config                      # عرض الإعدادات وما ينقصها
.venv/bin/qqq demo --days 5               # تشغيل كامل بلا أي مفاتيح (بيانات مولّدة)
.venv/bin/qqq backtest --start 2026-01-05 --end 2026-03-31 --mode ai
.venv/bin/qqq snapshot --day 2026-03-02 --at 10:30
```

`qqq demo` يشغّل السلسلة كاملة (بيانات ← مؤشرات ← انتباه ← حواجز ← عقل ← إدارة صفقة
← تقرير) على بيانات مولّدة، فيثبت أن الأنابيب سليمة قبل دفع ريال واحد للبيانات.

## البنية

```
src/qqq_alpha/
├── config.py              كل الإعدادات، لا أرقام سحرية في الكود
├── domain.py              نماذج البيانات المشتركة بين كل الطبقات
├── data/
│   ├── massive.py         عميل Massive/Polygon مع إعادة محاولة وتراجع أسّي
│   ├── pricing.py         Black-Scholes + تسعير تاريخي حقيقي
│   └── synthetic.py       مولّد جلسات للتجريب بلا اشتراك
├── features/
│   ├── indicators.py      EMA / RSI / ATR / VWAP / MACD / حجم نسبي
│   ├── levels.py          مستويات الشارت محسوبة كأرقام
│   ├── flow.py            كشف الحيتان: Sweeps و Blocks واتجاه التدفق
│   └── snapshot.py        يجمع كل شيء في MarketSnapshot واحد
├── brain/
│   ├── playbook.yaml      الخبرة المتراكمة — بيانات لا كود
│   ├── attention.py       متى نوقظ الـ AI (بوابة تكلفة، ليست بوابة قرار)
│   ├── rails.py           حواجز أمان تنفيذية فقط — لا رأي سوقي فيها
│   ├── prompts.py         صياغة حزمة الأدلة للـ AI
│   └── decider.py         العقل + خط أساس آلي للمقارنة
├── trades.py              دورة حياة الصفقة حتى الإغلاق
├── journal.py             سجل لا يُمحى: ما دخلناه وما تركناه ولماذا
└── backtest/              إعادة تشغيل التاريخ + تقرير الأداء
```

## المبدأ المعماري الأهم

الأنظمة السابقة تفشل لأنها تُصفّي الفرص قبل أن ينظر إليها شيء ذكي. هنا الفصل صارم:

| الطبقة | صلاحيتها | ما لا تملكه |
|---|---|---|
| `attention.py` | تحديد **متى** ننظر | لا رأي في الاتجاه، ولا ترفض صفقة |
| `rails.py` | منع المستحيل تنفيذيًا (سوق مغلق، عقد ميت، حد خسارة اليوم) | لا رأي سوقي إطلاقًا |
| `decider.py` (AI) | **كل** قرارات الدخول والخروج والاتجاه والعقد | — |

وكل لحظة رفضناها تُسجَّل ويُحسب لاحقًا ماذا كانت ستربح — ليجيب التقرير على السؤال
الذي تتجاهله معظم الأنظمة: **كم كلّفنا حذرنا؟**

## الحالة الحالية

- ✅ الطبقات الحسابية والعقل والحواجز وإدارة الصفقة ومحرك الاختبار التاريخي — تعمل
- ✅ `qqq demo` يمرّ من طرف إلى طرف بلا مفاتيح
- ⏳ تسعير العقود في الاختبار التاريخي لا يزال تقريبيًا (Black-Scholes). ربط أسعار
  العقود الحقيقية هو المهمة التالية، ولا يجوز الحكم على الاستراتيجية قبله
- ⏳ تدفق الخيارات المؤسسي يحتاج باقة Developer فأعلى
- ⏳ بوتات تلقرام والاشتراكات ولوحة الأدمن — مراحل لاحقة (انظر `docs/ROADMAP.md`)

راجع `docs/ARCHITECTURE.md` لتفاصيل التصميم و`docs/ROADMAP.md` لخارطة الطريق.
